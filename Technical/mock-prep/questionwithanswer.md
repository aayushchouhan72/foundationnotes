# Python Interview Questions — Topic-wise

## 1. Python Basics & Fundamentals

### Q1. What is Python?

**Answer:**  
Python is a **high-level, general-purpose, dynamically typed programming language**. It is used for web development, automation, data science, AI/ML, scripting, backend development, and more.

Example:

```python
name = "Ayush"
print(name)
```

---

### Q2. What are the key features of Python?

Important features are:

- Simple and readable syntax
- High-level language
- Dynamically typed
- Object-oriented
- Interpreted/bytecode-executed
- Platform independent
- Large standard library
- Automatic memory management
- Supports multiple programming paradigms
- Huge third-party ecosystem

---

### Q3. Why is Python called an interpreted language?

Python is commonly called interpreted because Python programs are executed by the **Python runtime**, rather than being directly compiled by the programmer into native machine code.

For CPython, the process is approximately:

```text
Python source code
       ↓
Parsing
       ↓
AST / compilation
       ↓
Bytecode
       ↓
Python Virtual Machine
       ↓
Execution
```

So saying simply **"Python is interpreted"** is useful for beginners, but technically Python also performs compilation to bytecode.

---

### Q4. What is the difference between compiled and interpreted languages?

**Compiled approach:**

```text
Source Code
    ↓
Compiler
    ↓
Machine Code
    ↓
CPU
```

**Typical interpreted/VM approach:**

```text
Source Code
    ↓
Interpreter / Compiler
    ↓
Intermediate representation
    ↓
Runtime / VM
    ↓
Execution
```

Examples:

- C → traditionally compiled directly to native machine code
- Python → compiled to bytecode and executed by its runtime
- Java → compiled to bytecode and executed by JVM

---

### Q5. Why is Python platform independent?

Python source code can generally run on different operating systems as long as an appropriate Python implementation exists.

For example, the same:

```python
print("Hello")
```

can run on:

- Windows
- Linux
- macOS

The Python interpreter/runtime handles the platform-specific details.

---

### Q6. What makes Python dynamically typed?

In Python, the **object has a type**, rather than the variable having a permanently declared type.

```python
x = 10
x = "hello"
x = 3.14
```

The same variable can reference objects of different types at different times.

---

### Q7. What is bytecode in Python?

Bytecode is an **intermediate representation of Python code** designed to be executed by the Python runtime.

Conceptually:

```text
print("Hello")
      ↓
Python source
      ↓
Bytecode
      ↓
Python runtime
```

Bytecode is **not the same as CPU machine code**.

---

### Q8. What is PVM (Python Virtual Machine)?

PVM stands for **Python Virtual Machine**.

It is the execution mechanism/runtime that executes Python bytecode.

Conceptually:

```text
.py
 ↓
Bytecode
 ↓
PVM
 ↓
Execution
```

The exact implementation depends on the Python implementation; the term PVM is commonly used when explaining CPython.

---

### Q9. What is a `.pyc` file?

A `.pyc` file contains **compiled Python bytecode**.

For example:

```text
program.py
```

may have cached bytecode under:

```text
__pycache__/program.cpython-xxx.pyc
```

The exact filename depends on the Python version and implementation.

---

### Q10. What is the purpose of the `__pycache__` folder?

`__pycache__` stores cached bytecode files generated by Python implementations such as CPython.

Example:

```text
project/
    main.py
    __pycache__/
        main.cpython-xxx.pyc
```

It can improve startup performance by avoiding unnecessary recompilation in some situations.

---

### Q11. How does Python execute a program internally?

A simplified CPython pipeline is:

```text
Source code (.py)
       ↓
Tokenization / Parsing
       ↓
AST
       ↓
Compilation
       ↓
Bytecode
       ↓
Python runtime
       ↓
Execution
```

The exact internals are more complex, but this is a useful mental model.

---

### Q12. What is source code?

Source code is the human-readable code written by a programmer.

Example:

```python

```

This is Python source code.

---

### Q13. What is machine code?

Machine code is instructions represented in a form that the CPU can directly execute.

Conceptually:

```text

```

Machine code is CPU architecture-specific.

---

### Q14. What is compilation in Python?

Compilation in Python generally means converting source code into an intermediate executable representation such as **bytecode**.

```text
.py
 ↓
compile
 ↓
bytecode
```

You can even inspect code objects using:

### Q15. What is parsing in Python?

Parsing means analyzing Python source code according to Python's grammar to determine its structure.

For example:

```python

```

The parser determines that this represents an assignment whose value is an addition expression.

## 2. Parse Tree, AST & Execution

### Q16. What is a parse tree?

A parse tree represents how source code follows the grammar of a programming language.

For example:

```python
x = 10 + 20
```

A simplified structure might be:

```text
assignment
├── identifier → x
└── expression
    ├── 10
    ├── +
    └── 20
```

---

### Q17. What is an Abstract Syntax Tree (AST)?

AST stands for **Abstract Syntax Tree**.

It represents the logical structure of source code while removing unnecessary grammatical details.

You can inspect Python's AST using:

```python
import ast

tree = ast.parse("x = 10 + 20")
print(ast.dump(tree, indent=4))
```

---

### Q18. Difference between parse tree and AST?

| Parse Tree                   | AST                                  |
| ---------------------------- | ------------------------------------ |
| Represents grammar structure | Represents logical program structure |
| More detailed                | More abstract                        |
| Contains grammatical details | Removes unnecessary syntax           |
| Used during parsing          | Used in later compilation/analysis   |

---

### Q19. What role does AST play in execution?

AST represents the structured meaning of source code and is part of the compilation pipeline.

Simplified:

```text
Source
 ↓
Parser
 ↓
AST
 ↓
Compiler
 ↓
Bytecode
 ↓
Runtime
```

ASTs are also useful for tools such as linters, formatters, analyzers, and code transformation tools.

---

### Q20. Is Python fully interpreted? Explain.

Not in the simplistic sense.

For CPython:

```text
Source code
     ↓
Compilation
     ↓
Bytecode
     ↓
Execution by Python runtime
```

Therefore, Python involves **compilation and runtime interpretation/execution**.

Calling Python an "interpreted language" is common, but technically incomplete.

### Q85. What is a ternary operator?

Python's conditional expression:

### Q87. What is truthiness?

Truthiness means how Python evaluates an object in a Boolean context.


---

### Q88. What is `match-case`?

`match-case` provides structural pattern matching.

```python
status = 2

match status:
    case 1:
        print("One")
    case 2:
        print("Two")
    case _:
        print("Other")
```

Available since Python 3.10.

---

### Q89. How is `match-case` different from `switch`?

Python's `match-case` is more powerful than a traditional simple switch because it supports **pattern matching**, not just equality checks.

---

### Q90. What is wildcard `_` in `match-case`?

```python
case _:
```

matches anything not matched by earlier cases.

It acts like a default case.

---

### Q91. Can `match-case` handle multiple values?

Yes.

```python
match day:
    case 1 | 2 | 3:
        print("Working day")
```

---

### Q92. When should `match-case` be used?

Use it when you have:

- Multiple patterns
- Structured data
- Clear pattern-based branching
- Multiple discrete cases

For simple conditions, `if-elif` may be clearer.

---

### Q93. Can `match-case` match patterns?

Yes.

For example, list patterns:

```python
match data:
    case [x, y]:
        print(x, y)
```

---

### Q94. What happens when no case matches?

If there is no matching case and no wildcard:

```python
match value:
    case 1:
        print("One")
```

nothing happens.

There is no automatic error merely because no case matches.

---

### Q95. Can `match-case` replace `if-elif` ladders?

Sometimes, but not always.

Use:

```text
if-elif
```

for general Boolean conditions.

Use:

```text
match-case
```

when pattern matching or discrete cases make the code clearer.

# 11. Shallow Copy & Deep Copy

### Q136. What is shallow copy?

A shallow copy creates a new outer object but nested objects may still be shared.

```python

```

---

### Q137. What is deep copy?

Deep copy recursively copies nested objects.

```python

b = copy.deepcopy(a)
```

---

### Q138. Difference between shallow and deep copy?

```text
Shallow copy
     ↓
New outer object
Nested objects may be shared


Deep copy
     ↓
New outer object
Nested objects copied recursively
```

Example:

```python
import copy

a = [[1, 2], [3, 4]]

b = a.copy()
c = copy.deepcopy(a)
```

---

### Q139. What happens in `a = b`?

No copy is created.

Both variables reference the same object.

```text
a ──┐
    ▼
  object
    ▲
b ──┘
```

---

### Q140. What happens in `a = b.copy()`?

A shallow copy is created for objects that support `.copy()`.

```text
a ──► object A
b ──► object B
```

The outer objects are different.

# 17. Tuple Comprehension

### Q179. What is tuple comprehension?

**Important interview point:** Python does **not actually have tuple comprehensions**.

This:

```python
(x for x in range(5))
```

is a **generator expression**, not a tuple comprehension.

Its type is:

```python
type(x for x in range(5))
```

which is:

```text
<class 'generator'>
```

If you want a tuple:

```python
t = tuple(x for x in range(5))
```

Now:

```text
(0, 1, 2, 3, 4)
```

### Compare:

**List comprehension:**

```python
[x for x in range(5)]
```

Result:

```text
[0, 1, 2, 3, 4]
```

**Generator expression:**

```python
(x for x in range(5))
```

Result:

```text
generator object
```

**Tuple:**

```python
tuple(x for x in range(5))
```

Result:

```text
(0, 1, 2, 3, 4)
```

So if an interviewer asks:

> "What is tuple comprehension?"

A good answer is:

> **Python has no dedicated tuple comprehension syntax. Parenthesized comprehension-like syntax creates a generator expression. To create a tuple, pass that generator expression to `tuple()`.**

# 18. `eval()` — Detailed Explanation

### Q180. What is `eval()`?

`eval()` evaluates a **Python expression provided as a string** and returns its result.

Basic example:

```python
x = eval("10 + 20")
print(x)
```

Output:

```text
30
```

The string:

```text
"10 + 20"
```

is treated as a Python expression.

---

### Example 2: Mathematical expression

```python
result = eval("5 * 10 + 2")
print(result)
```

Output:

```text
52
```

---

### Example 3: Using variables

```python
x = 10
y = 20

result = eval("x + y")
print(result)
```

Output:

```text
30
```

`eval()` can access names available in its evaluation environment.

---

### Example 4: Function call

```python
print(eval("len('Python')"))
```

Output:

```text
6
```

---

### `eval()` vs `int()`

Consider:

```python
x = "10"
```

Using:

```python
int(x)
```

means:

> Convert this string representation of an integer to an integer.

But:

```python
eval(x)
```

means:

> Evaluate this string as a Python expression.

For example:

```python
eval("10 + 20")
```

returns:

```text
30
```

while:

```python
int("10 + 20")
```

raises:

```text
ValueError
```

---

### `eval()` can evaluate expressions

For example:

```python
eval("2 ** 3")
```

works.

But statements such as:

```python
eval("x = 10")
```

are not valid for `eval()`, because assignment is a statement rather than an expression.

For executing arbitrary Python statements from a string, Python has `exec()`, but that is a separate mechanism and carries serious security considerations.

---

## ⚠️ Why should you be careful with `eval()`?

**Never blindly use `eval()` on untrusted user input.**

For example, this is dangerous:

```python
user_input = input()
eval(user_input)
```

Because the input isn't limited to harmless arithmetic. It can potentially execute arbitrary Python expressions with access to the evaluation environment.

For example, don't build a calculator for strangers using:

```python
eval(input())
```

as a security mechanism.

For safe mathematical expressions, use a restricted parser or purpose-built expression evaluator instead.
